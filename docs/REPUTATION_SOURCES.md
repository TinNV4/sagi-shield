# Reputation sources — phone-number and URL blocklists we could query

Researched 2026-09-23 against primary sources (official docs pages, terms-of-use pages, press releases, GitHub repos). Where a site could not be fetched, or a fact only appears in secondary reporting, it is marked **unverified**. This file exists so the `/check` phone and link tabs, the `services.py` enrichments and the pitch do not claim data access we do not legally have. Related: `docs/RELATED_WORK.md` (products), PLAN section 6 (rules) and section 9 (`/check` URL/phone floors).

Reading key for the tables: "callable" = a backend on Cloud Run may call it under the published terms; "bulk" = a file we could load into Firestore; "none" = app / website / extension only.

## 1. Google (contest stack)

### 1.1 Web Risk API — already used
- Owner: Google Cloud. Covers **URLs only**: "social engineering sites, like phishing and deceptive sites, and sites that host malware or unwanted software" (https://docs.cloud.google.com/web-risk/docs/overview).
- Access: REST. Lookup API (`uris.search`, sends the URL), Update API (`threatLists.computeDiff` + `hashes.search`, local hash prefixes), Submission API (report a phishing URL), Evaluate API.
- Auth / cost (https://cloud.google.com/web-risk/pricing): Lookup **free up to 100,000 calls/month**, then $0.50 per 1,000; `computeDiff` free; `hashes.search` $50 per 1,000; Submission "contact sales".
- Quotas (https://docs.cloud.google.com/web-risk/quotas): SearchUris and SearchHashes 6,000/min; ComputeThreatListDiff 600/min; EvaluateUri 600/min; SubmitUri 1,000/day and 100/min, per project.
- Terms: the overview states "The information returned by the Web Risk must not be redistributed." No non-commercial restriction (this is the commercial counterpart of Safe Browsing).
- Evaluate API (https://docs.cloud.google.com/web-risk/docs/evaluate-api): returns "a per-threat-type confidence score" for SOCIAL_ENGINEERING / MALWARE / UNWANTED_SOFTWARE "based on Safe Browsing blocklists, generative AI models, machine learning models and heuristic rules", but it is **"available in private preview to a limited set of customers ... Contact our sales team"**, and "Any URLs submitted to the Evaluate API may undergo additional processing, including crawls." Not usable for the contest without an allowlist; if we ever got it, note that Google crawls the URL (our "never fetch" rule would be delegated to Google, not broken by us).
- Update frequency: list diffs on demand; Google does not publish a refresh cadence on the pages read.
- Coverage of JP/VN phishing: Google does not publish per-country coverage. Our own Cloud Run test hit a Web Risk match on a known phishing URL (CLAUDE.md), but there is no data on recall for Japanese/Vietnamese campaigns.

### 1.2 Safe Browsing API (v4 / v5) — not usable
- Same lists as Web Risk, free, but "The Safe Browsing API is for non-commercial use only (meaning 'not for sale or revenue generating purposes')" (https://developers.google.com/safe-browsing/v4/usage-limits, repeated on https://developers.google.com/safe-browsing/reference for v5). Terms (https://developers.google.com/safe-browsing/terms) also require a warning that "the reliability and accuracy of the service cannot be guaranteed" and forbid treating a URL as unsafe unless updated "within the past thirty minutes".
- v4 is marked deprecated with a migration guide to v5 (https://developers.google.com/safe-browsing/v4). Default quota of 10,000 queries/day is **unverified** (secondary: https://jentic.com/apis/googleapis.com/safebrowsing).
- Verdict: we already pay for Web Risk; Safe Browsing would only be defensible if Sagi Shield were declared non-commercial, and a bank-facing `/precheck` API makes that hard to argue. Do not add it.

### 1.3 VirusTotal / Google Threat Intelligence — Google-owned, but the free tier is non-commercial
- VirusTotal is part of Google Cloud (search summaries of https://cloud.google.com/security/products/threat-intelligence and https://github.com/VirusTotal/gti-dev-kit; the product page itself was truncated on fetch, so the wording is **unverified**, the ownership is common knowledge since the 2018 Chronicle move). Covers URLs, domains, IPs, files; no phone numbers.
- Public API (https://docs.virustotal.com/docs/api-overview): free key by registering; "4 requests per minute" and "500 requests per day" (https://docs.virustotal.com/reference/public-vs-premium-api); **"The API must not be used in commercial products or services"**. The paid Google Threat Intelligence API (https://gtidocs.virustotal.com/reference/api-overview) removes the limits; pricing is "contact sales", tiers Standard / Enterprise / Enterprise+ (**unverified**, from secondary reseller pages).
- Verdict: a legitimate Google-stack enrichment only under a paid GTI licence. Not for the contest budget; mention in the roadmap as "Google Threat Intelligence for URL/domain context".

### 1.4 reCAPTCHA (Fraud Defense) — SMS Defense scores a phone number, but only for our own sign-ups
- https://docs.cloud.google.com/recaptcha/docs/sms-fraud-detection: SMS Defense "provides a risk score that indicates the likelihood of that phone number committing SMS toll fraud" (0.0 low to 1.0 high). Inputs: the phone number in E.164, a stable `accountId`, and a reCAPTCHA token from the browser. It answers "is this number about to abuse *my* SMS OTP flow", not "is this number a scammer calling my user"; the number must belong to the person interacting with our page.
- Tiers (https://docs.cloud.google.com/recaptcha/docs/compare-tiers): Essentials free up to 10,000 assessments/month without SMS Defense; Premium 0-10,000 free, 10,001-100,000 $8 flat, then $1 per 1,000, SMS Defense included ("requires an extra assessment").
- Verdict: not a reputation lookup for the phone tab. It would fit a later "trusted contact / family pairing by SMS" feature, not `/check`.

### 1.5 Google Verified Calls — discontinued
- Displayed a business name and reason for calling on Android. Carrier partners state it "was fully turned down from January 31, 2023" (https://support.telnyx.com/en/articles/5941652-google-verified-calls-faq, https://support.exotel.com/support/solutions/articles/3000112380-google-verified-calls-deprecated-; **secondary**, Google's own page now redirects to RCS for Business). No Google product exposes a scam-number lookup to third parties; Pixel Scam Detection is on-device and has no API (RELATED_WORK.md).

### 1.6 Other Google products checked
- No Google Cloud "phone number reputation" API exists. Firebase Phone Auth / Identity Platform verify possession of a number, not its reputation (not fetched; stated from product scope). Nothing in the Google catalogue covers bank-account blacklists.

## 7. What Sagi Shield can use today

*Status 2026-09-23: item 2 is implemented - `tools/load_phish_list.py` loads the monthly CSVs into Firestore (`phish_urls`, `phish_hosts`, hashed keys) and `/check` floors a listed URL or host at MEDIUM with the `reported_phishing_jpcertcc` / `reported_phishing_host_jpcertcc` flag. Last 12 months loaded: 28,479 URLs, 25,976 hosts.*

Ranked by legal certainty first, then usefulness. The contest wants Google Cloud; items 2-4 are optional enrichments and must degrade to nothing, like every other call in `services.py`.

1. **Google Web Risk Lookup API (URLs)** - already wired in. Keep it as the only URL reputation source in the demo; it is Google-stack, commercial-clean, free at our volume (100,000 lookups/month). State plainly that Web Risk is a global list and that our own URL-shape rules (lookalike, punycode, shortener, odd TLD) are what catch a fresh `vneid-xacminh.top` before any list does.
2. **JPCERT/CC phishurl-list (Japanese phishing URLs, CSV on GitHub)** - load the yearly CSVs into a Firestore collection keyed by normalised host + path hash, refresh on each new commit (quarterly), and surface a match as a `reported_phishing_jpcertcc` evidence flag with a MEDIUM floor (the URL is months old and may be dead, so never HIGH from this alone). No licence text exists: keep the data server-side, credit JPCERT/CC, and send a one-line question about redistribution. Useful for evaluation of the URL tab against real Japanese campaigns.
3. **PhishTank `checkurl` without a key (global phishing URLs)** - callable and commercial use is allowed by the FAQ, but registration is closed and the anonymous rate limit is low (HTTP 509 on overflow). Acceptable as an evaluation tool and as a best-effort enrichment behind a feature flag; not something to rely on in the demo. Drop it if the Cisco EULA, once read, disagrees with the FAQ.
4. **ChongLuaDao (Vietnamese URLs and phone numbers)** - only after written permission: the consumer terms are personal / non-commercial, but they advertise an enterprise API and already license the denylist to DNS and antivirus vendors. Until then, link to `chongluadao.vn` from the Vietnamese result screen as the place to report, which costs nothing and is what their site asks for.

Not usable today, keep in the roadmap with the reason: Tobila 迷惑情報データベース Web API (police-sourced Japanese numbers, ¥100k/month), フィッシング対策協議会 STIX feed (membership and vendor eligibility), Web Risk Evaluate API (private preview), Google Threat Intelligence (paid), tinnhiemmang.vn export (needs NCSC agreement), nTrust / SIMO (no third-party access). Never: OpenPhish and URLhaus free tiers (non-commercial), Safe Browsing (non-commercial), VirusTotal public key (non-commercial), and scraping telnavi / jpnumber / scam.vn (terms).

Consequence for the product text: the phone tab's honest states remain `unknown` / community-reported / overseas-prefix, and the roadmap slide should say "commercial number databases (Tobila in Japan, ChongLuaDao or NCA data in Vietnam) plug into `services.py` as enrichments; the verdict never depends on them".
