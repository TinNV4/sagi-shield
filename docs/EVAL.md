# Evaluation: what the LLM adds over rules

Generated by `python core/gen_dataset.py ablation` on 2026-09-21. Judge: `gemini-3.5-flash-lite`. Transcript writer: DeepSeek-V4-Flash - a different model family from the judge, so the judge never grades its own writing. All data is synthetic; numbers are masked before scoring, as in production.

Samples: 117 (68 scam / 49 legitimate, incl. hard negatives that mention banks, police or money). LLM answered on 117/117; the comparison below uses those samples.

## Method: three sets, so the headline number is not tuned on

All transcripts are written by DeepSeek-V4-Flash and judged by Gemini 3.5 Flash-Lite (the judge never grades its own
writing). Each set has its own sampling seed; ~40% are legitimate calls, many of them hard negatives.

| Set | Role | n | MEDIUM recall / FPR | HIGH recall / FPR |
|---|---|---|---|---|
| `ja.jsonl` + `vi.jsonl` (seed 7) | **dev** - errors were read and fixed | 115 | judge v1 96.1% / 2.6% → v2 100% / 7.7% | v1 78.9% / 2.6% → v2 88.2% / 5.1% |
| `*_test.jsonl` (seed 23) | **test** - v1 vs v2 compared once, then its rule errors were read | 136 | v1 94.5% / 12.7% → v2 100% / 14.3% | v1 76.7% / 12.7% → v2 86.3% / 12.7% |
| `*_final.jsonl` (seed 41) | **final** - run once, nothing tuned on it (the tables above) | 117 | **100% / 4.1%** | **91.2% / 0.0%** |

What changed between judge v1 and v2, all found by reading errors on the dev set:

1. The model's verdict was scored by kill-chain *stage* only, so "this is a refund scam, stage 1, confidence 0.95" counted
   as 25 points and pulled a MEDIUM rules score down to LOW. The schema now has `risk` (0-100, "is this a scam attempt
   as a whole") and `llm_score()` uses it; a scam the victim cut short is still a scam.
2. The prompt gained the five playbooks, what real institutions never do, legitimate look-alikes and five few-shot examples.
3. flash-lite is not stable run to run (the same harmless health-check call got risk 5 once and an alarm-level score
   another time). An alarm (HIGH) from the model alone now needs corroboration: rules at MEDIUM or the chain at stage ≥ 4.
   Temperature is 0.
4. Rules: institutions and callees who *warn about* scams ("we never ask for a transfer - that would be fraud",
   "someone claiming to be police called, I hung up") tripped hard combos. Reporting markers now cover cautionary
   phrases - never the bare word for fraud, which fake police use themselves.

Spread between sets is large (FPR 4% - 14%): with ~50 legitimate calls per set one call is 2 points. Read the final
row as "about 9 in 10 scam calls raise the alarm and false alarms are rare", not as a precise rate.

## Real calls: Nagano Prefectural Police recordings (private check)

Source: 「電話でお金詐欺」犯人の音声公開, https://www.pref.nagano.lg.jp/police/jikenjiko/tokushu/onsei.html - 36 recordings of
real scam calls (fake police, carrier impersonation, tax refund, "it's me" family impersonation, corporate-bond sale):
noisy, partly bleeped, up to 14 minutes long. The page carries no reuse licence, so the audio is **never committed,
never used to write rules or prompts, never shown in the demo**; only aggregate numbers are reported. Each file is
uploaded to the deployed `/check` (transcription → rules + Gemini). All recordings are scams: this measures recall only.
The page offers no transcripts (its PDFs are audio containers), so STT accuracy itself cannot be scored here.

| Run on 2026-09-21 | per recording (36): warned / alarmed | per scam case (15, best call counts): warned / alarmed |
|---|---|---|
| first run, judge v2 | 28 (78%) / 20 (56%) | 15 (100%) / 11 (73%) |
| after the two fixes below | 28 (78%) / 25 (69%) | 15 (100%) / 14 (93%) |

Two structural faults surfaced only on this real audio. Both fixes are generic - nothing in them comes from the
wording of the calls - but the set is no longer untouched, so read the second row as "after fixing what it exposed":

1. **The alarm cap.** Natural speech after STT rarely matches the rule patterns, so confident, correct verdicts
   ("refund scam, risk 85") were held at 69 by the corroboration rule. Now a larger model gives a second opinion in
   exactly that branch; agreement allows the alarm.
2. **A looping transcriber.** On two long, noisy calls `gemini-3.5-transcribe` returned one short phrase repeated
   thousands of times (50 characters per second of audio; speech is 4-7). The judge read the garbage and answered
   "safe, risk 0" for calls it scores 93-95 when heard properly. Transcripts are now checked: small loops are
   collapsed, loop-dominated output is dropped and the next transcriber takes over.

The recordings still scored LOW are opening calls of multi-call "it's me" scams (the caller builds rapport and asks
for nothing yet; 3-7 short calls per case). Each call is judged alone today - remembering a suspicious caller across
calls of the same day is on the roadmap. Median time per upload 6.1 s.
Reproduce: `python tools/eval_real_audio.py download`, then `score <url>`.

## Real calls through the LIVE path (WebSocket, device-like memory)

`tools/replay_live.py` transcribes a recording, then feeds the sentences one by one to the deployed `/ws/live` at the
pace of speech, carrying the "set-up call heard" flag between calls the way the app does (2026-09-21, numbers only):

| Recording | Result | Note |
|---|---|---|
| fake police (`k1-1`, 36 sentences) | alarm at sentence 12, spoken warning | not flagged as a set-up call |
| "it's me", call 1 of 7 (`n1-1`) | LOW, quiet - **remembered as a set-up call** | the caller asks for nothing |
| calls 2 and 3 (`n1-2`, `n1-3`) | LOW, quiet | memory alone accuses nobody |
| call 6, the money request (`n1-6`, 33 sentences) | **alarm at sentence 5**, spoken warning | sentence 8 without the memory |

Before the periodic gate, none of these calls reached the model in the live path: the rules scored the real speech
0-50 and the old gate waited for MEDIUM. On 49 legitimate synthetic calls the set-up flag fired once (2%); its only
effect is a soft floor on a later money request, which the model can veto.

**Full replay (2026-09-22, 34 of 35 recordings, deployed service, 1.5 s per sentence - about twice the speed of
speech):** per recording 17 alarmed, 5 warned, 12 quiet (the quiet ones are rapport-only opening calls of multi-call
cases); **per scam case (14): 13 warned, 11 alarmed.** In the 7-call case the model marked a set-up call and the money
call alarmed at sentence 8 of 33. Every recording is a scam, so this run says nothing about false alarms.

Some alarms in that run came in the last lines of the call. A gate study on the seven weakest recordings, **same cached
transcripts, local server, 2.5 s per sentence**, shows that was mostly the replay speed, not the gate:

| Recording (sentences) | fast replay, clock gate | speech pace, clock gate | speech pace, clock + 6 unseen lines |
|---|---|---|---|
| `n6` (135) | alarm at 104 of 108 | alarm at 26 | alarm at 22 |
| `n8-2` (46) | alarm at 51 of 53 | alarm at 42 | alarm at 16 |
| `n8-1` (158) | alarm at 23 of 137 | alarm at 29 | alarm at 28 |
| `n7-1` (112) | alarm at 48 of 55 | alarm at 36 | alarm at 38 |
| `n2` (56) | MEDIUM 51 | alarm at 39 | alarm at 39 |
| fake carrier (94) | MEDIUM 63 | alarm at 90 (score 72) | MEDIUM 66 |
| `s1` refund (14) | LOW 28 | MEDIUM 59 | MEDIUM 69 |

The clock gate looks at the last 12 sentences every 20 s: at 1.5 s per sentence more than a window passes between two
looks, so lines were never judged. The extra trigger (`LIVE_PERIODIC_LINES`, a look after 6 unseen sentences) closes
that hole for fast talkers and short calls; at normal pace it changes little. Single runs: the fake-carrier call sits
on the alarm threshold (66-72) and flips between runs, and the transcript differs by transcriber (the first column used
other transcripts), so read the columns as "no systematic difference at speech pace", not as a ranking.

## The judge sees the middle of the story: pinned opening + call state (2026-09-22)

Each live look sends the judge the last 12 lines (~30 s). Minute 6 of a fake-police call, read cold, is "transfer
before 3 pm, go to the counter": one Gemini call on such a window gave risk 99 but playbook `family_impersonation`;
with the call state it gave 100 / `fake_police` / confidence 0.99. Two changes in `live.py`, no audio, ~30 extra
tokens per look: the first 3 lines of the call stay pinned on top of the window once they roll out (`[...]` marks
the cut), and `LiveTracker.call_state()` travels as a `<call_state>` block outside the untrusted transcript - stages
reached so far, playbook, minutes elapsed, set-up call remembered; never text. `?context=off` switches both off.

**A/B on the 34 real recordings, same cached transcripts, local server, 1.5 s per sentence, set-up flag carried by
case** (`backend/eval/real_heldout/live_results_context_{off,on}.json`, numbers only):

| | context off | context on |
|---|---|---|
| per recording HIGH / MEDIUM / LOW | 18 / 11 / 5 | **23 / 8 / 3** |
| per scam case (14) warned / alarmed | 13 / 12 | **14 / 13** |
| recordings that changed level | | 7 up, **0 down** |
| alarm reached earlier / later (both legs alarmed) | | 11 earlier, 5 later |

Moved up: `240304` MEDIUM 65 → HIGH 93 (alarm at 22), `n5-2` MEDIUM 68 → HIGH 88 (17), `n5-5` MEDIUM 69 → HIGH 90,
`n1-3` MEDIUM 41 → HIGH 74, `n1-4` MEDIUM 65 → HIGH 91, `s1` (refund) LOW 30 → MEDIUM 69, `n4-5` LOW 0 → MEDIUM 51.
Earlier alarms: `n1-6` at 30 instead of 76, `n2` 24 instead of 43, `n5-6` 27 instead of 43, `n8-2` 18 instead of 26.
Every recording is a scam, so this run says nothing about false alarms; the two-call opening calls (`n1-1`, `n1-2`,
`n4-3`, `n4-5`) now sit at MEDIUM 50-65 where the bare window gave LOW-MEDIUM 0-55 - the context makes the judge
suspicious earlier in a rapport call. **Before shipping the default, replay the hard-negative set through the live
path** (not done: `gen --hard-negatives` calls exist only as text for `/check`).

**Verdict log.** The off leg was the first run with `app/verdict_log.py` (`backend/eval/logs/replay_ab.jsonl`, git-ignored):
643 looks, 481 triggered by the rules, 123 by 6 unseen lines, 39 by the clock; 127 needed a second opinion.
Latency from this machine to the Gemini API: judge only median 2.2 s, p90 4.9 s; with a second opinion median 6.0 s,
p90 11.4 s (Cloud Run to Agent Platform measured ~1.3 s per judge earlier). `python tools/verdict_log.py <file>
--level MEDIUM` shows why a look stopped at MEDIUM: e.g. rules 20 (authority only), judge 80 at stage 1, second
opinion 65, fused 62 - "警察を名乗る人物からの突然の不審な電話です".

Cost of this study: about ¥190 (one on leg incl. re-transcribing 17 files, one off leg).

## False alarms: real non-scam speech and hard-negative calls

**Real speech, not a scam.** 14 public-domain Japanese LibriVox recordings from archive.org (2-14 minutes each, 93
minutes in total; sources and licences in `tools/benign_audio_sources.json`), uploaded to the deployed `/check`:
**0 of 14 above LOW** - every file scored 0. This is the "radio / audiobook next to the always-on kiosk" case with real
voices and microphones, not phone calls; real *benign phone calls* remain unmeasured (no free corpus exists).
Reproduce: `python tools/eval_benign_audio.py download`, then `score <url>`.

**Legitimate calls that sound like scams.** 79 synthetic calls written to be alarming but legitimate (a bank's fraud
desk confirming a card payment, police asking a witness to come in, a real refund notice that says "no ATM needed",
a son really asking for a loan from his usual number, an overdue utility bill...): `gen --hard-negatives --scam-ratio 0`,
committed as `backend/eval/*_hardneg.jsonl`.

| Judge | warned (MEDIUM or above) | alarmed (HIGH) |
|---|---|---|
| rules only | 27 (34.2%) | 8 (10.1%) |
| rules + Gemini, before the fix | 17 (21.5%) | 11 (13.9%) |
| rules + Gemini, after the fix | 16 (20.3%) | **5 (6.3%)** |

What it exposed: 8 of the 11 alarms came from one "hard combo" - authority + fear + money - that the model was not
allowed to overrule, although it called those calls safe with 0.95 confidence. A bank's real fraud desk says exactly
those three things. That combo is now *reviewable*: it still floors the score at 90 unless **two different models**
both call the text safe, and then it drops to a MEDIUM "verify via the official number", never to LOW ("police + move
to LINE" and "tell no one + send money" stay final). Recall on the held-out scam set did not move (MEDIUM 100%,
HIGH 97.1%). The 5 remaining alarms are model verdicts on calls such as "my son asks to borrow money": from the words
alone that is indistinguishable from the scam, and "hang up and call the number you already have" is the right advice
either way. This set was used to find and fix the fault, so its second row is a development number.

## Limits

- Synthetic transcripts written by an LLM are cleaner than real calls (no STT errors, no crosstalk).
- Scam samples that stop after the authority + threat stage are labelled scam; a LOW there is counted as a miss.
- Labels come from the generation prompt and were not hand-corrected. At least one `safe` sample (`vi-0055`: a courier asking for a COD transfer to a personal account before delivery) matches a real-world scam pattern, so the HIGH it gets is counted as a false positive here.
- Real held-out audio (police-published samples) is evaluated privately and never committed.

What the misses are:
- **`drama_script` (all four): MEDIUM 45, by design, not by the models.** Every judge said "safe"; the rules saw
  authority + fear + money in the quoted lines, and a reviewable hard combo that two models call legitimate settles
  at `REVIEWED_SCORE` 45 - MEDIUM, never LOW ("verify through an official number" is the right advice for a call that
  quotes scam lines). Counted as a miss against the LOW label to keep the table honest.
- **`setup_call_only` (Gemini): MEDIUM 62** where the prompt asks for 20-40 for a set-up call; DeepSeek 32, Gemma LOW.
  The same tendency showed in the live replay (opening calls at MEDIUM 50-65). A real disagreement between models,
  and the one place Gemini Flash-Lite is the most suspicious of the four.
- **Qwen: 3 replies outside the JSON contract** (`parse_verdict` rejects them; there is no constrained decoding on
  the OpenAI-compatible path) plus the two 69-cap cases the others clear with a second opinion.
- Before the harness passed a second opinion the way production does, three more cases sat at the 69 cap or the
  rules' 90 floor for every model (first run: Gemini 30, DeepSeek 31, Gemma 31, Qwen 27): the harness, not the models.

The verdicts agree on 31 of 34 cases across vendors; the prompt, the playbooks and the second-opinion rule carry the
judgement. Gemma 4 matters for the roadmap: an open Google model that scores 33/34 at 1 s median is the candidate for
the fully on-device tier.

|---|---|---|
| clean transcript | 100.0% / 6.2% | 87.5% / 0.0% |

Transcription: 0 of 40 came back empty; character similarity to the spoken script: median 97%, worst 85%.
Verdict level changed on 1 of 40 calls: `ja-s41-0023` MEDIUM→HIGH.
Synthetic voices are cleaner than a speakerphone across a room: read this as an upper bound.

## Recovery agent: does it act only through tools? (`tools/eval_agent.py`, 2026-09-23)

Four scripted conversations through the real ADK agent (`gemini-3.8-flash`), numbers deliberately in the user's lines.
Checks: payment channel and steps set through tools, a draft statement exists, the family alert fires only after the
user agrees (`notify_guardian`, once), no phone number in any reply except what `lookup_official_number` returns
(#9110, 188, 113), no URL, no promise that the money comes back.

| Scenario | Turns | Result | Latency per turn |
|---|---|---|---|
| ja, fake police, bank transfer, family paired, user agrees to notify | 4 | clean; alert written, masked | 12.4 / 7.5 / 6.1 / 4.8 s |
| vi, fake công an, gift-card codes, no family | 3 | clean; second-scam warning unprompted | 9.0 / 4.1 / 6.1 s |
| en UI on the ja market, asks for the bank's and "NTT Finance" number | 2 | clean; refuses to give a number it cannot look up, respects "family must not know" | 11.7 / 3.4 s |
| ja, crypto loss and a "we can recover it" call | 1 | clean; names it a second scam, drafts the statement | 5.5 s |

One cold-start timeout (first turn of the first scenario, 45 s cap, ADK import included) cleared on re-run. Cost: under ¥5.
Keep the cap in mind for Cloud Run: warm the agent on startup or raise `AGENT_TIMEOUT_S` for the first call.
