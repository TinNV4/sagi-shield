# Evaluation: what the LLM adds over rules

Generated by `python core/gen_dataset.py ablation` on 2026-09-21. Judge: `gemini-3.5-flash-lite`. Transcript writer: DeepSeek-V4-Flash - a different model family from the judge, so the judge never grades its own writing. All data is synthetic; numbers are masked before scoring, as in production.

Samples: 115 (76 scam / 39 legitimate, incl. hard negatives that mention banks, police or money). LLM answered on 115/115; the comparison below uses those samples.

## Remaining errors of rules + LLM at MEDIUM (4)

- `ja-0004` scam/refund: rules LOW (20) → fused LOW (24)
- `vi-0001` scam/investment: rules LOW (0) → fused LOW (24)
- `vi-0052` scam/fake_police: rules MEDIUM (45) → fused LOW (26)
- `vi-0055` safe/safe: rules LOW (30) → fused HIGH (82)

## Limits

- Synthetic transcripts written by an LLM are cleaner than real calls (no STT errors, no crosstalk).
- Scam samples that stop after the authority + threat stage are labelled scam; a LOW there is counted as a miss.
- Labels come from the generation prompt and were not hand-corrected. At least one `safe` sample (`vi-0055`: a courier asking for a COD transfer to a personal account before delivery) matches a real-world scam pattern, so the HIGH it gets is counted as a false positive here.
- Real held-out audio (police-published samples) is evaluated privately and never committed.

## Reproduce

```bash
cd backend
python core/gen_dataset.py gen --lang ja --n 60 --generator fci --out eval/ja.jsonl   # optional: the committed set is eval/ja.jsonl + eval/vi.jsonl
python core/gen_dataset.py ablation --datasets eval/ja.jsonl eval/vi.jsonl --model gemini-3.5-flash-lite
```

A second, hand-written check of 15 hard cases (news reports, prompt injection, keyword-free ore-ore, Vietnamese OTP / investment scams) is in `tools/compare_llm.py`: Gemini 3.5 Flash-Lite 15/15, median 2.3 s.
